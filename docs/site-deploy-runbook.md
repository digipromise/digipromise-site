# DigiPromise site — deploy runbook (static pages on WordPress)

> **Source of truth:** private GitHub repo `digipromise/digipromise-site` (copy also on Malik's MacBook in ~/Projects/digipromise-site). Clone it, build, deploy, then commit + push every change.

Live since 2 Oct 2026. 20 English + 20 Arabic pages (7 agents incl. Lilia) are static HTML served by a small PHP router inside the WordPress theme. WordPress still runs underneath (admin, AI News blog posts at /category/ai-news/, ROI tool).

## Where things live (cPanel → File Manager)
- Theme folder: `public_html/wp-content/themes/aimo/`
- Router: `dp-router.php` (generated, do not hand-edit). It runs on WordPress `init` (priority 0) so old redirect rules from the one-page site cannot hijack new URLs. Previous version saved as `dp-router-backup-v1.php`.
- Pages: `dp-pages/*.html`, assets in `dp-pages/assets/`, sitemap `dp-pages/dp-sitemap.xml` (served at /dp-sitemap.xml)
- Agent mascots: `dp-pages/assets/mascot-<agent>.webp` (Set B "feather scales", AI-generated by Malik, cut out to transparent circles). The eyes are drawn on top by `dp-motion.js` and follow the cursor. To change a mascot, replace its webp (square, transparent, ball filling the frame, no eyes).
- Favicon (7 Oct 2026): `assets/favicon.ico` (16/32/48), `favicon-32.png`, `apple-touch-icon.png` (180), `icon-192.png`, `icon-512.png`, all cut from the project file "Logo Digipromise.png". Linked in the page head (build.py) and in the WordPress pages head (build_wpchrome.py).
- Switch-on line, at the end of `functions.php`:
  `require_once get_template_directory() . '/dp-router.php';`
- Backup of functions.php before launch: `functions-backup-2026-10-02.php`
- Backups (outside the public folder): `/home/digidcvp/private-backups/` — old DB dump, full-site zip, and one `dp-pages-vN-date` copy before every publish (latest: `dp-pages-v27-2026-10-17`). Never store backups inside public_html.

## To publish an update
1. If CSS/JS changed, bump `VER` in build.py (now '18') so browsers fetch the new files (assets cache 7 days).
2. Rebuild the package (`LIVE=1 python3 build.py && python3 build_wpchrome.py`, zip `dp-router.php` + `dp-pages/`).
3. **Before uploading, check the server for files changed outside this build** (cPanel → File Manager, sort `dp-pages/` and `dp-pages/assets/` by date). Copy any such change into the local source first, or the zip will overwrite it. (8 Oct 2026: widget.js had been changed on the server by the system project.)
4. Copy the current `dp-pages` to `private-backups`.
5. cPanel → File Manager → `themes/aimo/` → Upload the zip → Extract (overwrites). **Give every zip a new name** (next: dp-live-v31.zip): the uploader does not overwrite an existing zip with the same name, so Extract would unpack the old one.
6. Cloudflare → Caching → Configuration → Purge Everything (pages are cached at Cloudflare for 4 hours).
7. Check the live pages in an incognito window.

## Digi voice call (17 Oct 2026, v27)
- Widget header has a "🎙 Talk" pill (AR "🎙 تحدث") next to WhatsApp/Telegram (`#digiTalk` in partials_widget.html; voice bar `#digiVoice`; CSS at the end of widget.css; JS at the end of widget.js).
- Click → mic permission → `POST https://engine.digipromise.com/webhook/voice-session` `{agent:"digi",page}` → `{signed_url}` → ElevenLabs `Conversation.startSession({signedUrl, connectionType:'websocket'})`, loaded on demand from `https://cdn.jsdelivr.net/npm/@elevenlabs/client@1.26.0/+esm` (pinned version).

- Endpoint 404 or unreachable → "Voice calls are coming soon. Please use chat for now." `{error}` or failure → "Voice is busy, please use chat."

## Light only on phones (13 Oct 2026, v25)
The site has no dark design. Every page (and the WordPress blog head) sends `<meta name="color-scheme" content="only light">`, and dp.css / dp-chrome.css set `:root{color-scheme:only light}`, so phone browsers in dark mode (Samsung Internet, Chrome auto-dark) don't repaint it dark. Keep these if the head is rebuilt.

## Site forms -> engine (13 Oct 2026, v23)
- Contact form (`/contact/`, `/ar/contact/`) and homepage hero box (EN/AR) POST JSON to `https://engine.digipromise.com/webhook/site-form` via `window.DP_SEND()` (end of dp.js).
- Fields: name, email, phone, company, message (agent + plan are folded into message), page, ref (from `?ref=` / DP_REF), plus hidden honeypot `website` (class `.hp`). Homepage box sends what the visitor typed as `email`; the engine treats it as a phone if it has no "@".
- Engine replies `{"ok":true}` or `{"ok":false,"error":"..."}`. On ok the site redirects to `/thanks/` (`/ar/thanks/`), a noindex page (`'always_noindex': True`, kept out of the sitemap). On error it stays on the form and shows the error. `/thank-you/` (WordPress) is only for Stripe purchases. Engine needs an email or a phone and only accepts digipromise.com / www.
- Leads land in app.digipromise.com → DigiPromise (Internal) → Leads (same list as Digi chat leads). Email/WhatsApp alerts are the engine's job.
- WhatsApp is no longer the submit action; it stays as a separate "Chat on WhatsApp" button (number to change when the new DigiPromise number is bought).

## Refund policy (7 Oct 2026, live at /refund-policy/ + /ar/refund-policy/; lawyer to review)
- Promise: not satisfied or changed your mind → cancel any time and get the remaining amount back under these rules. No go-live guarantee.
- Setup fee: non-refundable (scope is agreed with the client before it is charged). One setup fee when the same agent has two plans (Stella in + out).
